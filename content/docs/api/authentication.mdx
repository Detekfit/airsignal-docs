---
title: Authentication
description: Two credentials — collect with appId, send with an nsk key. Never mix them.
---

AirSignal uses **two separate credentials**, each scoped to different routes. Pick the right one
for the call you are making.

## Credentials

<ApiSection title="Collect (SDK)">
  <ApiField name="X-AirSignal-App-Id" type="string" required defaultValue="app_YOUR_APP_ID">
    Public App ID. Used for config, subscribers, subscriptions, heartbeat, sessions,
    unsubscribe, and engagement. Never send the REST key on these routes.
  </ApiField>
</ApiSection>

<ApiSection title="Send (server)">
  <ApiField name="Authorization" type="string" required defaultValue="Key YOUR_REST_API_KEY">
    Project REST key with the `Key` prefix (`nsk_…`). Used only for
    `POST` / `GET /v1/notifications`. See [API keys](/docs/guides/api-keys). HTTP Basic
    `base64(appId:nsk_…)` is also supported.
  </ApiField>
</ApiSection>

```headers.http
# SDK collect
X-AirSignal-App-Id: app_...

# Server send
Authorization: Key nsk_...
```

<Callout type="warning">
  Never ship `nsk_...` inside a mobile or web client release build. Collect routes do not accept
  the REST key, and send routes do not accept `X-AirSignal-App-Id` as authorization.
</Callout>

## Collect auth errors

All `/v1` collect routes return a nested camelCase error:

```response.json
{ "error": { "code": "appNotFound", "message": "..." } }
```

| Condition | HTTP | `error.code` |
|---|---|---|
| Missing / blank header | 401 | `invalidAppId` |
| App id not in database | 404 | `appNotFound` |
| App exists but disabled | 401 | `appDisabled` |

Branch on `error.code` — never parse the message text.

## Conventions

| Topic | Rule |
|---|---|
| JSON casing | camelCase everywhere |
| Content type | `application/json` |
| Timezones | IANA strings (e.g. `Asia/Dhaka`) |
| Platform values | `android` \| `ios` \| `web` (engagement also allows `email`) |
| Deletes | Public API is soft-unsubscribe only; hard delete is dashboard-only |
