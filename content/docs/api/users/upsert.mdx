---
title: Upsert subscriber
sidebarTitle: Upsert subscriber
method: POST
description: Create or update a subscriber and optionally attach a push subscription.
---

Register a device and optional identity fields. Identity resolves in this order: matching
`subscriberId` → existing device by `subscriptionId` → existing device by `pushToken` → create
new. Upsert does **not** switch a device onto a different `externalId` — use
[Login](/docs/api/users/login) for that.

## Request parameter

<RequestParam name="subscriberId" type="UUID">
  Persist and resend the AirSignal subscriber id returned from a previous upsert.
</RequestParam>

<RequestParam name="subscriptionId" type="UUID">
  SDK-internal device id. Persist it privately per device. Never use it for send targeting.
</RequestParam>

<RequestParam name="externalId" type="String">
  Your user id. Prefer [Login](/docs/api/users/login) when switching a device onto an account.
</RequestParam>

<RequestParam name="pushToken" type="String">
  FCM / APNs push token for this device.
</RequestParam>

<RequestParam name="pushEnabled" type="Boolean">
  Whether the OS currently allows notifications for this app.
</RequestParam>

<RequestParam name="email" type="String">
  Optional email on the subscriber profile.
</RequestParam>

<RequestParam name="name" type="String">
  Optional display name.
</RequestParam>

<RequestParam name="device" type="Object">
  Device metadata such as `platform`, `model`, `os`, `language`, `timezone`, and `country`.
</RequestParam>

<Callout type="tip">
  `subscriptionId` is SDK-internal. Use `subscriberId` or `externalId` when targeting sends.
</Callout>
