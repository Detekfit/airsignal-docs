The `airsignal_flutter` package (`^0.5.0`) is the single dependency your Flutter app needs for
push. It owns push receive internally, so you do **not** add `firebase_messaging` or ship
`google-services.json` yourself.

<Callout type="warning">
  Requires a Google service account uploaded on your app — see
  [Get a Google service account JSON](/docs/guides/service-account).
</Callout>

<Callout type="info">
  **Android** is supported today. **iOS** is not ready yet — do not rely on push there.
</Callout>

## Installation

<Steps>
  <Step title="Add the dependency">
    ```install.sh
    flutter pub add airsignal_flutter
    ```
  </Step>
  <Step title="Android setup">
    No manual Firebase setup is required — the package bundles what it needs to receive push via
    FCM. Make sure your app's Android `applicationId` matches the Android app registered in the
    Firebase project used for your [service account](/docs/guides/service-account).
  </Step>
  <Step title="iOS / Web">
    <Callout type="warning">
      iOS and Web are on the platform roadmap. The collect API contract is already stable for
      them — see [API Reference](/docs/api).
    </Callout>
  </Step>
</Steps>

<Callout type="info">
  Do not add `firebase_messaging` yourself. Push receive and token refresh live inside
  `airsignal_flutter` — a second messaging plugin will conflict with it.
</Callout>

## Initialization

Register click / foreground listeners **before** `initialize` so cold-start opens are delivered.

```main.dart
import 'package:flutter/widgets.dart';
import 'package:airsignal_flutter/airsignal_flutter.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  Airsignal.notifications.addClickListener((event) {
    // User opened a notification.
  });

  Airsignal.notifications.addForegroundWillDisplayListener((event) {
    // Push arrived while the app is open.
  });

  await Airsignal.initialize(appId: 'app_...');

  runApp(const MyApp());
}
```

`Airsignal.initialize` talks to the hosted API (`https://api.airsignal.dev` — fixed, not
host-configurable), loads push client config, obtains an FCM token, and registers a subscriber
automatically.

| Argument | Default | Purpose |
|---|---|---|
| `appId` | required | Public app id from the AirSignal dashboard |
| `showNotificationOnForeground` | `true` | Show a system tray banner while the app is open |

On a bad / unknown app id, `initialize` throws `AirsignalCollectAuthException` with
`code` of `appNotFound`, `invalidAppId`, or `appDisabled` — switch on `e.code` /
`AirsignalErrorCode`, not the message text.

### Reading the subscriber id

```main.dart
final subscriberId = Airsignal.user.subscriberId;
// or: Airsignal.pushSubscription.subscriberId
```

Persist this alongside your own user record if you plan to target sends by `subscriberId` from
your backend. See [Subscribers](/docs/api/subscribers) for the full identity model.

## Identity

A newly initialized device starts **anonymous**. Call `login` once you know who the user is (for
example, right after your own app's sign-in completes).

### Login

```main.dart
await Airsignal.login('user_123');
```

This attaches the current device's push subscription to the subscriber identified by
`externalId`, creating the account if it doesn't exist yet. Multiple devices can share the same
`externalId` after each logs in.

### Logout

```main.dart
await Airsignal.logout();
```

Moves the device to a brand-new anonymous subscriber. The identified account is kept even if it
now has zero devices — logout does **not** delete data or opt the user out of push.

<Callout type="warning">
  `login` / `logout` change **which account this device belongs to**. To stop sending push to this
  device, use [optOut](#opting-out).
</Callout>

### Profile

```main.dart
await Airsignal.user.setEmail('user@example.com');
await Airsignal.user.setName('Ada Lovelace');
await Airsignal.user.setPhone('+15551234567');
```

### Tags and aliases

```main.dart
await Airsignal.user.addTags({'plan': 'pro', 'cohort': 'beta'});
await Airsignal.user.addTags(['vip', 'beta']); // value-only tags

await Airsignal.user.removeTags(keys: ['cohort']);
await Airsignal.user.removeTags(values: ['vip']);

await Airsignal.user.addAliases({'facebookId': '102938'});
await Airsignal.user.removeAlias('facebookId');
```

Use tags and aliases for segmentation and cross-system linking — see
[Subscribers](/docs/api/subscribers) for server-side equivalents.

## Push & engagement

### Requesting permission

```main.dart
final granted = await Airsignal.notifications.requestPermission();
```

Call this at a sensible point in your onboarding flow. On grant, the SDK registers the push token
with `pushEnabled: true`. On deny, it soft-unsubscribes push for this device.

```main.dart
final status = await Airsignal.notifications.getPermissionStatus();
// "granted" | "denied" | "notDetermined"
```

### Foreground display

While the app is open, foreground pushes fire
`addForegroundWillDisplayListener` and (by default) also show a tray banner.

Call `event.preventDefault()` **synchronously** in that listener to suppress the tray when it
would otherwise show. Background / killed deliveries always use the system tray when the OS
delivers them.

### Handling taps / launch URLs

```main.dart
Airsignal.notifications.addClickListener((event) {
  final notification = event.notification;
  final launchUrl = notification.launchUrl;
  final actionId = notification.actionId; // androidButtons tap, if any
  final data = notification.additionalData;
});
```

A tap opens either the `https` `launchUrl` in the system browser **or** your app — never both.
When a link opens and your app was not already running, the click listener receives the event on
the next app launch (within 24 hours). Action-button taps always open the app.

Opening a notification automatically reports a `clicked` (or `buttonClicked`) engagement event —
you don't need to call the events API yourself from Flutter.

### Action buttons

If a send included `androidButtons`, button taps are reported the same way as a regular click,
with the tapped id on `notification.actionId`. See [Notifications](/docs/api/notifications) for the
send-side payload shape.

<Callout type="info">
  Dashboard **Delivered** counts come from FCM accept confirmation, not from the SDK. The SDK only
  ever reports clicks, not delivery or receipt.
</Callout>

### Opting in / out

```main.dart
await Airsignal.optOut(); // soft-unsubscribe this device from push only
await Airsignal.optIn();  // re-enable push if OS permission is granted
```

`optOut` always soft-unsubscribes **push only** (`?pushOnly=true` under the hood) — it does not
opt the subscriber out of email. Logout is separate and does **not** call `optOut`.

## Debug logging

```main.dart
Airsignal.debug.setLogLevel(AirsignalLogLevel.verbose);
```

Levels: `none`, `error`, `warn` (default), `info`, `verbose`.
