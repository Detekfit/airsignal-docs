The Web SDK is loaded from `https://cdn.airsignal.dev/sdks/web/v1/airsignal.js`. After the page loads it shows
a card on your page. Subscribe opens the browser permission dialog.

<Callout type="warning">
  Save the **Site URL** on the app's Web platform page first (for example `https://example.com`).
  It must be the exact origin: `https://www.example.com` and `https://example.com` are different
  sites. The site must be served over https. `http://localhost` works for local testing.
</Callout>

## Installation

Pick **one** option on the app's Web platform page. A site uses one option, not both.

### Option 1 — Your own site

Use this when you can upload a file to your site root.

1. Download `AirSignalSDK.js` from the app's Web platform page and upload it at your site root,
   so it opens at `https://example.com/AirSignalSDK.js`.
2. Paste the head script below on every page.

The browser asks for permission on your own site.

### Option 2 — Blogger or sites without file upload

Use this when you cannot upload files (Blogger, some site builders). Paste the head script below
on every page. Nothing to upload, and no DNS to set up.

Subscribe opens a small window on your app's push address, for example
`https://0123456789abcdef0123456789abcdef.airsignal.top`, which the dashboard shows. The browser asks for
permission for that address. Each app gets its own push address.

### Head script

Paste this exact block in the `<head>`. Replace only `YOUR_APP_ID` with the public app id from the
app settings page. Leave the script address as `https://cdn.airsignal.dev/sdks/web/v1/airsignal.js`.

```html
<script src="https://cdn.airsignal.dev/sdks/web/v1/airsignal.js" defer></script>
<script>
  window.AirSignalDeferred = window.AirSignalDeferred || [];
  AirSignalDeferred.push(function (AirSignal) {
    AirSignal.init({ appId: "YOUR_APP_ID" });
  });
</script>
```

## Initialization

`init` shows the card after the page loads. Cancel hides it in this browser only. Subscribe opens
the browser permission dialog.

| Argument | Default | Purpose |
|---|---|---|
| `appId` | required | Public app id from the dashboard |
| `autoPrompt` | `true` | Set `false` to show nothing until you call `requestPermission()` |

To ask from your own button, call `requestPermission()` on click:

```html
<script>
  AirSignalDeferred.push(function (AirSignal) {
    AirSignal.init({ appId: "YOUR_APP_ID" });
  });
</script>
<button onclick="AirSignalDeferred.push(function (s) { s.requestPermission(); })">
  Enable notifications
</button>
```

```js
AirSignalDeferred.push(async function (AirSignal) {
  const status = AirSignal.getPermission();
  // "default" | "granted" | "denied" | "unsupported"
  const subscriberId = AirSignal.getSubscriberId();
});
```

Persist `subscriberId` if you target sends by id from your backend. See [Users](/docs/api/users).

## Identity

A new browser starts **anonymous**. Call `login` after your own sign-in completes.

### Login

```js
AirSignalDeferred.push(async function (AirSignal) {
  await AirSignal.login("user_123");
});
```

Attaches this browser's push subscription to the subscriber for that `externalId`, creating the
account if it does not exist yet.

### Logout

```js
AirSignalDeferred.push(async function (AirSignal) {
  await AirSignal.logout();
});
```

Moves this browser to a new anonymous subscriber. The identified account is kept. Logout does
**not** stop push.

<Callout type="warning">
  `login` / `logout` change which account this browser belongs to. To stop push, use
  [optOut](#opting-in--out).
</Callout>

### Tags

```js
AirSignalDeferred.push(async function (AirSignal) {
  await AirSignal.setTags({ plan: "pro", cohort: "beta" });
  await AirSignal.removeTags(["cohort"]);
});
```

## Opting in / out

```js
AirSignalDeferred.push(async function (AirSignal) {
  await AirSignal.optOut();
  await AirSignal.optIn();
});
```

`optOut` stops push for this browser only. It does not change email subscription. Logout does
**not** call `optOut`.

<Callout type="info">
  A click is reported automatically. Dashboard **Delivered** counts come from the push service
  accepting the send, not from the page.
</Callout>
