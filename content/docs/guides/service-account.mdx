---
title: Get a Google service account JSON
description: Create and download the Firebase/Google Cloud service account credential AirSignal needs to send push through FCM.
---

AirSignal sends push through **Firebase Cloud Messaging (FCM)** using a Google service account
that you upload once per app. This page shows you how to create that credential.

<Callout type="info">
  This is a one-time dashboard setup step, not something your app's code does. It's required
  regardless of which client SDK or platform you use.
</Callout>

<Steps>
  <Step title="Open (or create) a Firebase project">
    Go to the [Firebase console](https://console.firebase.google.com) and select an existing
    project, or create a new one. This project should already have the platform apps you plan to
    push to registered (e.g. an Android app with its package name) if you want
    `GET /v1/config/push` to resolve platform-specific client config.
  </Step>
  <Step title="Open project settings">
    Click the gear icon next to **Project Overview** → **Project settings**.
  </Step>
  <Step title="Go to Service accounts">
    Select the **Service accounts** tab.
  </Step>
  <Step title="Generate a new private key">
    Click **Generate new private key**, then confirm. Firebase downloads a `.json` file — this is
    your service account credential.

    <Callout type="warning">
      Treat this file like a password. Don't commit it to source control or share it outside your
      team. AirSignal encrypts it at rest and never returns it through any API response.
    </Callout>
  </Step>
  <Step title="Upload it to AirSignal">
    In the AirSignal dashboard, open your app (or create one — see
    [Create an app](/docs/guides/create-an-app)), choose **Google push (Messaging)** as the
    platform, and upload the downloaded JSON file.
  </Step>
</Steps>

## What this unlocks

Once uploaded, AirSignal can:

- Send notifications to devices registered against this app
- Serve public Android client config via `GET /v1/config/push` (uses the same Google project)

## Rotating or replacing the credential

If the key is ever compromised, generate a new one in the Firebase console (step 4) and re-upload
it on the app — this replaces the stored credential without changing your `appId`.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Notifications accepted but never arrive on device | Service account belongs to a different Firebase project than the one your app's `google-services.json` / push token was issued from |
| `GET /v1/config/push` missing Android fields | No Android app registered in the Firebase project yet |

<Callout type="tip">
  Using the Flutter SDK? Host apps do **not** add `firebase_messaging` or ship
  `google-services.json` themselves — see
  [Flutter installation](/docs/sdks/flutter/installation).
</Callout>
